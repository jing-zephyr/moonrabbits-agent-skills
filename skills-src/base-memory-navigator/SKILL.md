# 基座记忆导航（Base Memory Navigator）

> ⚠️ **待应用草案** —— 本文件是 `base-memory-navigator\SKILL.md` 的**通用化改写版**（v0.1.0 → v0.2.0）。
> **改写原因**：原版是"为某一台机器写的技能"，含硬编码本机路径、平台计费概念与用户画像，**不可分发**。
> **本次改写共 7 处**，逐条列在文末附录（不随文件发布）。

## 核心原则

**先问后读，读索引不读资产。宁可问一句，不可搜全盘。**

一句话解释为什么：**全盘搜索是上下文预算里最贵的一种动作** —— 它一次读进大量无关内容，
而这些无关内容会挤掉真正相关的部分。**问一句话的成本，永远低于搜一遍盘。**

## 触发后流程（必须按顺序）

### 1. 先问用户（只问一个问题）

> 「这个任务需要我读共享记忆吗？如果你知道答案在哪份文档，直接告诉我路径，那是最便宜的。」

**不许跳过这一步直接开搜。**

### 2. 用户说"读"（或未明确说"不读"）→ 按顺序读**索引层**

索引层的总量应当很小（**建议 < 30KB**），**必须顺序读完，禁止跳读**：

| 顺序 | 读什么 | 说明 |
|---|---|---|
| 1 | 记忆基座的**使用说明** | 定义了这个基座的组织方式与三条铁律 |
| 2 | 基座的**开机卡 / 索引** | 新会话的入口 |
| 3 | 收件箱 / 归档目录的**文件名列表** | **只看文件名，不打开文件**。命名规范本身即目录 |

> 🔴 **第 3 步最关键**：文件名列表本身就是索引。
> 若命名规范是"日期-来源-主题"，那么**光看文件名就能完成 80% 的定位**，一份都不用打开。

### 3. 只点开与当前任务相关的 1–2 份索引文档

其余**不看**。看完不够再回来点第二份，**不要一次全开**。

### 4. 需要「资产本体」前，先报告并获批准

资产本体 = 视频 / 音频 / 压缩包 / 大文档。

**动手前先向用户报告三件事**：①这个文件多大 ②我要用它做什么 ③预计花多少时间。
**获批准后才动手。**

### 5. 开工前向用户「复述对齐」（必须执行）

> 「我从记忆里了解到：①…②…③…（**不超过三点**）。对吗？」

用户纠正后，**以用户说法为准**。

> 这一步不是客套。它把"我读到的"和"你以为我读到的"对齐 ——
> **省掉的是后面一整轮返工。**

## 禁止行为（写死，不靠自觉）

| 禁止 | 为什么 |
|---|---|
| **禁止全盘搜索**（递归 grep / find 整个磁盘找"印象中的文件"） | 这是上下文预算里最贵的动作，一次盲搜可能抵掉几十次定向读取 |
| 禁止凭"印象"猜路径 | 猜错要重来，比问一句贵得多 |
| 禁止编造记忆里不存在的内容 | 找不到就是找不到 |
| 禁止未经许可读取视频/音频/压缩包等大文件 | 它们可能很大，且可能含用户私人素材 |
| 索引里找不到的 → **问用户** | 问是人最便宜、机器最贵的动作；反过来才对 |

## 输出契约

| 段 | 内容 |
|---|---|
| **【我读了什么】** | 列出实际打开的文件（**含没找到的**，如实说） |
| **【我了解到的】** | 不超过三点 |
| **【需要你确认】** | 复述对齐的问题 + 任何未决项 |

## 与其他技能的边界

| 情况 | 交给谁 |
|---|---|
| 检索**外部**知识（文献、文档库） | 知识库检索类技能 |
| 校验历史结论**有没有出处** | `source-verifier` |
| 需要**改写**已检索到的内容 | `audience-adapter` |
| 本技能只做一件事 | **定位**（在哪），不做**判断**（对不对） |

## 为什么这个技能值得存在

官方口径（NVIDIA Agent Skills 训练营）：

> 「常驻 = description 约 **100 token / 技能**；
> **没有人会全装 343 个技能，按需安装 + 目录路由才是工程上的正确解。**」

本技能把这句话从**原则**变成了**动作**：
- 它自己常驻只占 description（≈100 token）
- 它教 Agent **不要**一上来就把整个记忆库读进来
- 它的核心动作（**读文件名而非文件**）是"目录路由"最直接的一种实现

**上下文不是免费的。省下来的上下文，才是真正能用来思考的部分。**
