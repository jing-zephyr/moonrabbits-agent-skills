# 基座记忆导航（Base Memory Navigator）

## 核心原则

**先问后读，读索引不读资产。宁可问一句，不可搜全盘。**

## 触发后流程（必须按顺序）

1. **先问用户一个问题（只问一个）**：
   > 「这个任务需要我读协作基座（`D:\202608OPC项目\_基座\`）的记忆吗？
   > 如果你知道答案在哪份文档，直接告诉我路径，那是最便宜的。」

2. 用户说"读"（或未明确说"不读"）→ 按顺序读**索引层**（总量 < 30KB，禁止跳读）：
   1. `_基座\00-使用说明.md`
   2. `_基座\新窗口开机卡.md`
   3. `_基座\05-过程库\_收件箱\` 的**文件名列表**（文件名即目录：日期-平台-主题）

3. 只点开与当前任务相关的 1-2 份索引文档。其余不看。

4. 需要**资产本体**（视频/音频/压缩包/大文档）前：
   向用户报告"文件多大、我要用它做什么"，**获批准后才动手**。

5. 开工前向用户**复述对齐**（必须执行）：
   > 「我从基座了解到：①…②…③…（不超过三点）。对吗？」
   用户纠正后，以用户说法为准。

## 禁止行为（写死，不靠自觉）

- **禁止全盘搜索**：递归 grep/find 整个磁盘找"印象中的文件"——这是最大的积分浪费，一次盲搜可能烧掉几十次定向读取的额度
- 禁止凭"印象"猜路径、编造记忆中不存在的内容
- 禁止未经许可读取视频/音频/压缩包等大文件
- 索引里找不到的：**问用户**，不许编

## 用户背景（一句话）

用户是非技术背景、多 AI 窗口并行工作；跨窗口共享记忆全部在 `D:\202608OPC项目\_基座\`，90+ 份交接文档按"日期-平台-主题"命名。
